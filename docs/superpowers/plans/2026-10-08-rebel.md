# ReBeL on Leduc - Implementation Plan

> Written for the record: the plan was executed by the session that wrote it (autonomous work, pre-approved). The
> boxes are ticked as executed; deviations from the first draft of the plan are noted under the task they hit.

**Goal:** ReBeL (Brown et al. 2020) for Leduc, with Kuhn as the smoke-test game: self-play over public belief states,
Linear CFR-D search with a value network at the end of the betting round, exact evaluation of the test-time policy.

**Architecture:** One new module, `headsup/algos/rebel.py`: range bookkeeping, the public tree of a betting round
(`RoundTree`), a solver for many subgames at once with a callable for the leaf values (`CFRD`), the vectorised
self-play walk (`sample_leaf`), the value network and replay, and the `ReBeL` class with its CLI. It reuses exact
best response (`headsup/algos/best_response.py`) and `_load_optimiser` (`headsup/algos/deep.py`); the game is read
through the game protocol only. `headsup/algos/leduc_report.py` gets a ReBeL section.

**Spec:** `docs/superpowers/specs/2026-10-08-rebel-design.md`

## Review Focus

1. **The leaf query.** Current iterate, both ranges normalised, the traverser as agent, the answer times the
   OPPONENT's reach. `test_leaf_query_uses_the_current_iterate_and_scales_by_opponent_reach`.
2. **Card removal.** Fold and showdown values, the chance average (`1 / (C - 2)`, the surviving opponent mass, no
   own card), ranges after the board card, the card's distribution. `test_profile_values_match_the_game`,
   `test_ranges_after_actions_and_the_board_card_match_brute_force`.
3. **Which iterate.** Self-play: uniform over `0 .. T`; play and evaluation: even steps with weight `j + 1`; the
   last round's mixture is the average after `T - 2` steps, not `T`.
   `test_stopping_step_distributions`, `test_exact_mixture_is_the_expectation_of_the_playthroughs`.
4. **The stored target** is `root_mean`, for both agents, also for hands without own mass.
   `test_self_play_stores_the_averaged_root_values_of_every_pbs`.
5. **Ranges of size zero.** An explored action the iterate never takes leaves a range without mass: it must
   become uniform, never NaN. `test_exploration_is_by_exactly_one_player`.
6. **Not testable here:** `--device cuda:0` (the session is CPU-only by instruction).

### Task 1: Ranges and the public tree of a betting round

- [x] `normalise` (the official `1e-80`), `bayes_update`, `board_distribution`, `sample_board`, `deal_board`,
  `chance_average`, `stop_weights`.
- [x] `RoundTree(state)` from the game protocol: node kinds, children, stakes read off `returns()` (the tree is
  built from hands that cannot tie), betting histories, pots; index arrays for the reach gathers.
- [x] Tests: trees against the games; reach = product of own action probabilities; ranges after a betting line and
  the board card against the enumerated joint distribution.

### Task 2: The solver

- [x] `CFRD`: the official `CFR::step` vectorised over subgames and hands; `leaf_fn(p, beliefs)` for the leaves;
  `values(p, sigma)` for a fixed profile; `record` keeps the iterates.
- [x] Tests: a random profile's root value = the game's `expected_value` (Leduc through both rounds and the chance
  average, Kuhn); Kuhn = the repo's tabular Linear CFR; the `1e-80` floor; `root_mean`'s weights; the leaf query.
- Deviation from the draft: the first version kept the subgame axis first; gathers along a middle axis made a
  step cost 9 us per subgame. The arrays are now subgame-last inside the solver (1-2 us), subgame-first at its
  interface.
- Finding: with the official floor the solver is NOT identical to textbook Linear CFR (strategies at decisions the
  opponent's iterate does not reach differ), so the floor became a parameter and the identity test uses 0.

### Task 3: Search with exact leaf values (the calibration)

- [x] `ReBeL.solver / search / solve_boards / exact_leaf`, `policies()` (exact mixture, unsafe), `table()`.
- [x] `--oracle`; test at T = 64; T = 1024 measured once (22.1 mA/g, unsafe 54.5; the brief: 21.8 and 53.5).
- Finding: the brief's prototype is not reproducible to the digit at small T. Two causes: it passes ranges
  without mass down as zeros (the official code and this solver make them uniform), and - with that emulated -
  the two implementations agree to 1e-14 for three steps and then drift apart by a factor 10-100 per step: the
  search with exact leaves amplifies rounding differences.
